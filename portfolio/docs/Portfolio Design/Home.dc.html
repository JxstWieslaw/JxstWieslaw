02 — How I work

Tested, typed, and shipped with a rollback plan.

Three habits that follow me into every codebase.

Habit 01

Tested by default

  • ▸TDD with JUnit and Mockito — the test written with the feature, not after it.
  • ▸Shift-left: integration tests run on every push, against the contract rather than the implementation.
  • ▸Honest error handling: failures surface with context instead of being swallowed.
Habit 02

Architecture that stays legible

  • ▸Typed backends — the contract lives in the code, not in a document nobody opens.
  • ▸SOLID and the boring patterns — Factory, Strategy, Repository — over cleverness.
  • ▸Migrations reversible by design — dry-run, apply, rollback — so no release is a one-way door.
Habit 03

Owned to production

  • ▸Docker, CI/CD and cloud deployments — Azure, AWS — treated as part of the feature, not a hand-off.
  • ▸Monitoring, alerting and disaster recovery rehearsed before launch, not after an incident.
  • ▸Handover documentation written while the context is still fresh.

How I run a project

  1. 01
    Discovery

    Constraints, users, and the one thing that must not break.

  2. 02
    Architecture

    Data model, boundaries, migration strategy. Written before code.

  3. 03
    Delivery cadence

    Staged builds, weekly demo, review as the default unit of work.

  4. 04
    Launch

    Rollback rehearsed, logging in place, on-call agreed.

  5. 05
    Operate

    Monitored, measured, and handed over so it outlives me.

I deviate when the problem asks for it — Node when the team lives in TypeScript end to end, MongoDB when the data is document-shaped, GraphQL when clients over-fetch, Three.js and React Three Fiber when the interface should move. Not because something is new.
