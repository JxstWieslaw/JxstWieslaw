# Mission: profile system design (2026-10-17)

Repo: JxstWieslaw/JxstWieslaw (the GitHub profile README). Profile: `content`.

## Question

Which system design should the profile use, and what else improves it?

## Options considered

| Option | Verdict |
|---|---|
| A. Hand-written README + third-party widgets (current) | Simple, but widgets die silently. Already lost github-readme-activity-graph (HTTP 402) this month. |
| B. README generated by a scheduled Action (self-built SVGs, committed to the repo) | Removes the dependency, but adds a build pipeline, a token and a bot committing to the repo, for one page. |
| C. A + automated guard (chosen) | Keep the README hand-written; make decay loud. |

## Decisions

1. **Keep the README static and hand-written (A), add a guard (C).** For a single page
   that changes a few times a year, a generator is more machinery than the problem
   deserves. The real risk is silent decay, so it gets an automated check.
2. **`scripts/check-readme.mjs` + `.github/workflows/readme-check.yml`.** Runs on PRs
   that touch the README and weekly (Mondays 06:00 UTC). Fails on dead or non-image
   widget URLs (3 attempts each) and on leftover merge-conflict markers. A failed
   scheduled run emails the owner; no issue-bot, no token. The checkout action is
   pinned by SHA.
3. **Counter badges are excluded from the check** (hits.sh, komarev.com): fetching
   them from CI would inflate the view count.
4. **`portfolio/` is git-ignored.** A nested clone of the portfolio repo sat untracked
   here and was committed as an empty gitlink once (reverted in `356da0f`). Ignoring it
   stops that recurring.
5. **Tech Stack is a category table** (6 rows) instead of six stacked lists, to
   shorten the page without dropping any badge.
6. **Branch flow:** PR to `develop`; the `develop -> main` release PR is left for
   Wieslaw (no `auto_main`).
